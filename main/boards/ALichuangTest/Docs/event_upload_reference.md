# ALichuangTest 事件上报参考文档

本文档整理了ALichuangTest机器人板所有上报的事件类型和对应的文本描述。

## 概述

EventUploader负责将设备的交互事件上报到云端服务器，每个事件包含：
- **事件类型** (`event_type`): 英文标识符，便于程序处理
- **时间信息**: 事件开始/结束时间和持续时间
- **情感状态**: 可选的二维情感空间信息（效价值+激活度）

**注意**: 事件文本描述仅用作参考，实际上报的JSON中不包含`event_text`字段，文本描述由云端根据事件类型进行映射和维护。

## 事件持续时间计算

不同事件的持续时间计算方式：

| 事件类型 | 持续时间来源 |
|---------|------------|
| 触摸事件 (TAP/LONG_PRESS/CRADLED) | 从TouchEventData.duration_ms字段获取实际触摸持续时间 |
| 挠痒事件 (TICKLED) | 固定2000ms（检测窗口时间） |
| 运动事件 | 固定0ms（瞬时事件） |

## 事件缓存和上报机制

### 缓存策略
- **缓存时间**: 最大5秒，超时事件自动清理
- **缓存大小**: 最大50个事件（可配置）
- **批量发送**: 每批最多10个事件

### 上报时机
1. **立即上报**: 当网络连接可用时
2. **缓存上报**: 网络断开时缓存，连接恢复后批量上报
3. **过期清理**: 超过5秒的事件被丢弃

### JSON格式示例
```json
{
  "session_id": "device_session_1234567890",
  "type": "lx/v1/event",
  "payload": {
    "events": [
      {
        "event_type": "Touch_Left_Tap",
        "start_time": 1234567890123456,
        "end_time": 1234567890123456,
        "emotion_state": {
          "valence": 0.5,
          "arousal": 0.3
        }
      }
    ]
  }
}
```

### JSON字段说明
- **session_id**: 会话标识符，用于关联同一会话中的多个消息
- **type**: 消息类型，固定为 "lx/v1/event" 表示事件上报
- **payload**: 载荷数据，包含实际的事件信息
  - **events**: 事件数组，可包含多个事件
    - **event_type**: 事件类型标识符
    - **start_time**: 事件开始时间（微秒时间戳）
    - **end_time**: 事件结束时间（微秒时间戳）
    - **emotion_state**: 可选的情感状态信息
      - **valence**: 效价值 [-1.0, +1.0]
      - **arousal**: 激活度 [-1.0, +1.0]

## 情感状态集成

每个上报的事件可以包含当前的二维情感状态：
- **效价值 (Valence)**: [-1.0, +1.0]，负值表示消极情感，正值表示积极情感
- **激活度 (Arousal)**: [-1.0, +1.0]，负值表示低激活，正值表示高激活

情感状态由EmotionEngine根据事件类型动态更新，并同步到EventUploader中。

## 设备标识

- **设备ID**: 固定为 "alichuang_test_device"
- 可以通过配置系统修改为其他唯一标识符
- 用于在多设备环境中区分不同的机器人

## 调试和监控

EventUploader提供详细的日志输出，包括：
- 事件处理过程的调试信息
- JSON构建和验证结果
- 网络发送状态
- 缓存管理操作

通过ESP_LOG系统可以实时监控事件上报的完整流程。
