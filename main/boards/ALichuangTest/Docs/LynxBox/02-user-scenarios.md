## 用户故事 1: 基本语音对话交互 (P1优先级)

### 规格定义
用户首次使用AI语音盒子与毛绒玩具进行语音对话,实现自然的双向对话交互。

### 验收场景实现分析

#### SC-001: 开机播放开机音乐
```
Given: 盒子处于关机状态
When: 用户拨动开关至ON位置
Then: 盒子立即开机并播放开机音乐
```

**实现状态**: ⚠️ **待确认**

**需要验证**:
1. 是否有硬件拨动开关电路
2. 是否有开机音乐资源文件
3. 开机流程中是否自动播放

**建议实现位置**:
- `application.cc` - 在启动流程中添加开机音乐播放
- `main/assets/[lang]/boot.ogg` - 添加开机音效资源

---

#### SC-002: 开机联网后播放问候语
```
Given: 盒子已完成网络配置并开机
When: 开机成功联网后
Then: 盒子主动播放后台准备的"问候语"
```

**实现状态**: ⚠️ **部分实现**

**当前实现**:
- ✅ WiFi连接状态检测 - 继承自`WifiBoard`
- ✅ 设备状态管理 - `application.cc`中的状态机
- ⚠️ 联网后主动问候 - 需要验证是否实现

**代码位置**:
- `wifi_station.cc` - WiFi连接事件回调
- `application.cc` - 状态转换逻辑

**建议改进**:

#### SC-003: 语音对话响应时间≤1.5秒
```
Given: 盒子已开机并完成网络配置
When: 用户说"你好"
Then: 盒子在1.5秒内通过扬声器回应
```

**实现状态**: ✅ **已实现**

**性能依赖**:
- ✅ 双麦克风阵列 - ES7210 ADC
- ✅ Opus编码 - 低延迟音频编码
- ✅ WebSocket协议 - 流式传输
- ✅ 流式TTS播放 - 边接收边播放

**性能指标** (NFR-001要求≤2秒):
- 音频采集: ~20ms (20ms帧长)
- Opus编码: <10ms
- 网络传输: 50-100ms (正常网络)
- ASR识别: 200-500ms (云端)
- LLM生成: 300-800ms (流式)
- TTS合成: 100-300ms (首包)
- 网络下载: 50-100ms
- 音频播放: 即时

**总延迟**: 约720-1830ms ✅ 符合1.5秒要求

**代码位置**:
- `audio/audio_service.cc` - 音频采集和播放管道
- `protocols/websocket_protocol.cc` - 流式数据传输

**性能指标** (NFR-002要求≤500ms):

**代码位置**:

**实现状态**: ✅ **已完整实现**


```
SC-025: 休眠状态摇晃玩具 → 唤醒并进入配网模式 (未联网)
SC-026: 摇晃唤醒 → 等同于拿起唤醒
SC-027: 唤醒后自动重连WiFi
```

**实现状态**: ✅ **已实现基础功能**

**休眠机制**:
- ✅ 空闲检测 - `event_engine.cc:182` (idle_threshold_us_)
- ✅ 1分钟无交互触发IDLE事件
- ✅ 可配置空闲阈值

**唤醒机制**:
- ✅ IMU持续采样 (休眠时降低采样率可省电)
- ✅ 拿起检测 (`MOTION_PICKUP`)
- ✅ 摇晃检测 (`MOTION_SHAKE`)

**配置示例**:
```json
// event_config.json:163

  "detection": {

  }
}
```

**WiFi重连**:
- ✅ 继承自`WifiBoard`的自动重连机制

**需要优化**:
- ⚠️ 休眠时关闭WiFi降低功耗 (spec.md:357行建议)
- ⚠️ 唤醒后快速重连优化 (目标<2秒)
